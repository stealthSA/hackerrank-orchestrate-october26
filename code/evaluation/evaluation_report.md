# Evaluation report

Method: `python3 code/evaluation/evaluate.py` runs the full pipeline and compares it with labelled answers.
*Step-level* = exact match of (phase, system, resource, operation, state, evidence) tuples; *field-level* = per-field
accuracy over steps aligned on (phase, system, resource, operation); *sequence* = the whole ordered `steps_json` and
the status equal the label. The 518 evaluation requests have no public labels, so accuracy is measured on the 32
public sample cases and on custom cases; the full run is checked structurally by `validate_output.py`.
This report is regenerated by `python3 code/evaluation/make_reports.py`.

## Full run (518 evaluation requests)

* Output: INCOMPLETE 355, COMPLETE 153, NOT_APPLICABLE 10;
  3260 steps in total. The 10 non-deletion requests are exactly those the privacy intake
  classified as non-deletion in `system_activity.csv`.
* `validate_output.py`: 518 rows checked, 0 problems (sorted ids, valid JSON, consecutive step numbers,
  phase/operation order, every cited evidence id exists and was captured at or before `audit_at`, COMPLETE rows fully
  evidence-backed, INCOMPLETE remediation/verification steps carry no evidence).
* Links that had to be resolved by the deterministic tie-break because no evidence separates the candidates:
  {'activity:account': 150, 'activity:policy': 57}. These are the main source of expected errors against the hidden labels.

## Failures found and improvements made

| Finding | Improvement | Measured effect |
| --- | --- | --- |
| First intent classifier rejected 7 genuine follow-up requests ("my profile still appears when I search") | Default to deletion context; explicit declines and other-intent cues override | now flags exactly the 10 non-deletion requests |
| Evidence from snapshots exported after `audit_at` was cited because the in-file snapshot time was earlier | Visibility is decided by the manifest `captured_at` of the evidence item | step F1 0.74 -> 0.88 |
| Account anchoring used too few calibration pairs and a strict status mapping | Link over all known requests, calibrate the window on explicit pairs, soft status match, elimination | F1 0.88 -> 0.94 |
| Lookup-style evidence (handover, ledger) was interpreted from raw attributes (attachment treated as exposed PII, flows/backups ignored) | Use the lookup `record_type` / `result` | status accuracy 96.9% -> 100%, F1 0.94 -> 0.987 |
| Retained audit records missing from INCOMPLETE cases (only visible in later evidence) | Retained records are linked from any evidence date but cited only when visible | recall +6 pts |
| Policy-action anchoring attached analytics records to INCOMPLETE cases | Anchor only cases whose explicit evidence is already compliant | removed false steps |
| Screenshots/PDFs: OCR noise, one-record documents, statement numbers instead of ids | Row-local identifier windows, catalog display-reference aliases, OCR-tolerant matching, catalog system names | export, attachment, tombstone, marketing cases resolved |
| Duplicate request of one subject collided on the same account event | Requests of one subject at one reported time are one deletion | custom_01-03 pass |
